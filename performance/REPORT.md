# PetaBoard 読み込み性能の調査・検証記録

対象はユーザー回答「HTMLが対象です」に基づく `peta-board.html`。外部本番サイトのデプロイ・本番サイト改善率は対象外。HTMLへの反映と、HTMLを直接開く隔離環境での比較を行う。既存の未コミット変更を含む開始時のHTMLを変更前とし、Git HEADとは比較しない。

## 実施結果

HTMLへの反映、実際のファイルを直接開いた機能確認、変更前後の再計測を完了した。反映ファイルは `peta-board.html`、最終版SHA-256は `8f1701691d10f1e7652817b615cfaf85d94733cd44a75c1c9655d9fde813faaa`。公開URL・外部配布先は特定されていないため、外部サイトへの本番反映・本番サイト計測は実施していない。以下はローカルHTMLの実測であり、公開サイトの改善率ではない。

変更前は `54979e5917e9c6305666f57e84a5d843debbdeca01a7ba397a7457f21790b822`。2026-10-09（JST）00:54に最初の変更前記録を保存し、終了条件を精緻化した最終比較は01:35〜01:38、補足計測は02:10まで行った。反映後の実ファイルで保存・操作・復旧を検証した。

[全画面・全条件の結果表（262行）](results.md)と[CSV](results.csv)に、主要内容・操作可能・結果取得を分け、中央値、短縮率、前後の回数、最小〜最大を記録した。すべての比較条件で前後5回ずつ計測した。画面間の改善率を平均していない。

代表例：1440×900・500件・初回の主要内容表示は、付箋編集202.0→24.1ms（88.1%短縮）、期限カレンダー120.7→6.2ms（94.9%）、設定を閉じた後のヘルプ186.2→20.9ms（88.8%）、初期化確認162.2→1.9ms（98.8%）。ボード673.2→677.7ms（−0.7%）、検索56.1→59.5ms（−6.1%）、検索解除783.5→835.9ms（−6.7%）は範囲が重なり、改善未確認。

連続操作後の500件・1440px再読み込みは592.2→629.1ms（−6.2%）で悪化を観測した。保存・描画の静定を待ち、版を交互に測った追加比較は651.1→648.1ms（0.5%）で範囲が重なり、持続的な悪化は未確認。両条件を結果表に残した。初回にヘルプだけを開く場合は旧版でも遷移が省略されることがあり、上記88.8%を全経路に適用しない。

## 動作確認と残る課題

全13表示スナップショットの文字列・件数・順序・検索強調が一致した。0／50／500件、320／375／1440pxのカード・本文・列の寸法とスクロール範囲も差なし。実ファイルで11件の通常機能確認と6件の開閉・復元・フォーカス確認が成功し、JavaScriptエラーなし。保存再読込、全データのJSON一致、別タブ更新、破損原文の退避、保存不能時の警告、無効／容量超過JSON拒否、開き直し、Tab・Esc・日付選択を確認した。空ボードでは追加した下書きの編集とカレンダーを別条件で測り、キャンセル後0件を確認した。

長文500件の初期表示は約0.7秒、検索解除は約0.8秒が残る。主因は本文とカードのレイアウト。主要候補を実測したが、表示・寸法を維持する変更では安定した追加効果が得られなかった。仮想化・遅延描画はスクロール、読み上げ、後続操作への影響を伴い、今回の維持条件では採用していない。実スマートフォン、Safari、実利用データによる遅いケースの分布は未検証。

## 計測条件と終了条件

同一のMac上のChrome 154.0.8037.99（Playwright、headless、CPU／ネットワークの人工的制限なし）を使用する。1440×900と375×812は同じ端末のビューポート設定であり、後者は実際のスマートフォンの測定ではない。

0件・50件は4列、500件は12列。50件は短い本文・3チェック項目、500件は長い本文・各30チェック項目の負荷が大きい代表ケース。500件は列あたり41〜42件。500件のJSONは3,475,569 bytesで本文2,400〜2,800文字・各2タグ。全ケースは合成データで実ユーザーの保存領域を使わない。データ生成は `measure.cjs` の `fixture()` を参照する。実利用データやSafari・タッチ実機・スクリーンリーダーでの性能評価は実施していない。

基本の連続手順はボード→設定→閉じる→ヘルプ→閉じる→編集→カレンダー→閉じる→検索→解除→設定→初期化確認→キャンセル。再読み込みはこの手順後に行う。検索は専用計測で入力欄へのフォーカスが静定してから同じ検索語を入力し、以前のモーダルのフォーカス復帰の影響を除く。

変更前後は同じ `file:///private/tmp/peta-board-performance.html` にHTMLを置いて比較する。ファイル名・ブラウザー・データ・操作順をそろえ、処理を並列実行しない。最終HTMLの実際のパスでの機能確認も別途行う。

初回は新しいブラウザーコンテキストで、localStorageに同じ合成データを事前配置し、IndexedDBのリビジョンDBは未作成。再読み込みは同じコンテキストで、前回作成されたリビジョンDBと保存済みデータを維持。初回と再読み込みを分ける。file URLのためHTTP・CDN・サーバーキャッシュは存在しない。OSのファイルキャッシュ、Chrome内部の最適化、端末の背景負荷は制御していない。localhost計測は予備調査として別扱いで、最終比較へ混ぜない。

| 指標 | 開始 | 終了 |
| --- | --- | --- |
| ボード・主要内容 | ナビゲーションのperformance.timeOrigin | 正しいボード名と全件の描画が完了した最初の描画フレーム。件数を照合 |
| ボード・操作可能 | 同上 | 画面のinertが解除され、初期化とイベント登録が完了した描画フレーム。後続の実操作で機能も検証 |
| 検索・解除 | ブラウザー内でinputイベント／解除クリックを開始 | 正しい件数・結果・順序のDOMが更新された後の描画フレーム（2回のrequestAnimationFrame） |
| ダイアログ・主要内容 | 対象ボタンのブラウザー内click | is-openかつパネルのopacity=1になった描画フレーム。カレンダーは直接表示を確認 |
| ダイアログ・操作可能 | 同上 | is-open、非inert、pointer-events有効になった描画フレーム。後続操作が受け付けられることも検証 |

loadイベントや通信終了は完了指標にしない。描画フレームの記録は実ディスプレイを撮影した計測ではない。ダイアログの予備計測は表示途中の2フレームまでだったため、最終結果はアニメーション完了／操作受付を分けた定義で再計測する。変更前の最初の記録は `before-file-original.json` に保管する。

判定は前後の最小〜最大が重ならず、相対差5%以上かつ絶対差5ms以上の場合に改善／悪化とする。それ以外は改善未確認。これは今回の控えめな判定規則で、統計的信頼区間ではない。

短縮率は `(変更前の中央値 - 変更後の中央値) / 変更前の中央値 * 100`。負値もそのまま報告する。各画面・条件をまとめた全体改善率は作らない。ばらつきの範囲で説明できる差は改善未確認とする。

補足の単独ヘルプは実際にボタンへフォーカスしてから開き、操作可能をイベント登録・フォーカス移動・非inertの即時状態で判定する。内容表示は引き続き不透明になった描画フレームで判定。基本表のフレーム観測による操作時間の小さな負値もそのまま残す。

JSON復元はファイルchangeから正しい確認内容、確定clickから全件と正しいボード名の表示・保存まで。バックアップはclickからダウンロード完了と全JSONの照合までで、自動化との往復を含む補助値。別タブは送信側編集開始から受信側の正しいタイトル描画までで、既存の160ms保存待ちを含む。エラー条件はナビゲーションから正しい警告／復旧内容の表示と操作準備までを測る。

## 原因と候補

確認した事実：500件の予備プロファイルではLayoutDuration=1,069.75ms、カード生成約8.9ms、正規化約4.7ms、検証約6.6ms。renderBoardは約1,094msで、スクロール復元時のレイアウト確定が大部分。長い本文のレイアウトが主要な待ち時間を占める。検索では件数と一覧のために同じ500件の照合が2回行われる。外部通信・サーバー待ち・画像・N+1取得はない。

推論：縦並びのGridと長文の内在サイズ計算がボトルネック。各候補をブラウザーで実測した。

| 候補 | 範囲・見込み | 負担・正確さ・運用 | 判定・根拠 |
| --- | --- | --- | --- |
| Gridの幅・行の最小値、本文最大高さの明示、CSS containment | 初期表示・再描画 | 小。表示を確認 | 大きな短縮は未確認。profile-*.json、css-candidates.json |
| 全列を常にFlexへ変更 | 初期表示・検索解除 | 小。カード高さ・スクロール範囲が変わる | レイアウト時間は減ったが既存寸法を変えるため見送り |
| カードDOMの再利用・検索照合の共有 | 再描画・検索 | 中。全フィールド・列・検索語・日付の失効処理、DOM保持のメモリー増加 | JS時間は減ったが利用者の待ち時間は改善未確認。最終版には含めない |
| 列・リストも保持した差分更新 | 再描画 | 中。入力・並べ替え・フォーカスの保守負担 | 5回比較で待ち時間改善未確認。最終版には含めない |
| 高密度列だけ、既存と同じ84px行を使うFlex | 多数の付箋の初期表示・検索・解除 | 小。0／50／500件・3幅の寸法は一致 | 10組の交互比較では改善未確認。375px幅の起動は悪化し、元に戻した |
| ダイアログの開閉待ちを除去 | 編集・設定・ヘルプ・確認・カレンダー | 小。内容、フォーカス、入力・保存・状態管理を維持。フェードと移動アニメーションを省く | 最終変更。フレーム待ち、100〜140msの表示遷移、160msの終了タイマーを除去 |
| 仮想化、見えない本文の切り捨て、遅延描画 | 長文・大規模ボード | 大。スクロール／後続操作へ遅延を移し、検索・読み上げ・表示に影響 | 見送り。文章・データ・描画対象を省略しない |
| 保存検証・リビジョン確認の省略 | 起動時の十数ms | データ保護・同期・復旧を損なう | 採用しない |

## 変更と復旧

最終変更は、準備済みのダイアログを同期的に表示し、フォーカスを移す。ダイアログと背景のフェード、パネルの移動、カレンダーの100ms遷移を取り除き、閉じるときも直ちに非表示にする。これにより、内容が用意できた後の1フレーム待ち・100〜140msの表示待ち・160msの閉じ待ちを除く。表示し切った時点のマークアップ・スタイル・寸法・内容は維持する。トースト、ツールチップ、ボタンの状態遷移は変更しない。

非同期の古い開閉タイマーで再度開いた画面を隠すこともなくなる。`modalOpenings`と`deferFocus`のガードは残し、閉じた直後の新しい操作・再表示を古いフォーカス復帰で上書きしない。データ取得・保存・同期・検証・検索・ボード描画の処理は開始時のコードに戻してあり、採用していないキャッシュやレイアウト最適化を含めない。

問題があれば、同じファイル名のまま `performance/before.html` を `peta-board.html` に戻して再読み込みする。保存済みJSONやIndexedDBの消去・移行は不要。表示／順序／操作の不一致、スクロール範囲の差、再計測での明確な性能悪化を復旧条件とする。

## 検証の保存先

- `before.html`: 開始時HTML。ユーザーの未コミット変更を含む復旧元
- `before-file.json`, `after-file.json`: HTML直接起動の生計測、版のSHA-256、Chrome版、日時、全条件
- `before-modals.json`, `after-dense-modals.json`: ダイアログ定義の精緻化と不採用候補の比較。最終比較には最終版の `*-file.json` を使用
- `before.json`: localhostの予備計測。最終改善率には使用しない
- `after-cache-only-file.json`, `after-dense-file.json`, `paired.json`, `candidate-check.json`, `profile-*.json`, `css-candidates.json`: 不採用候補・原因の調査記録
- `geometry*.json`, `parity.json`: 寸法・全表示文字列・件数・順序・検索強調の照合
- `verification.json`, `verification-file.json`: localhostと実際のHTMLでの機能検証
- `search.json`, `io.json`, `errors.json`, `stable.json`, `empty-editor.json`: 最終版の補足計測。各版のSHAと日時・生データを含む
- `modal-verification.json`: 最終実ファイルでのフォーカス、即時開閉、不正復元拒否の確認
- `measure.cjs`, `search.cjs`, `io-measure.cjs`, `errors.cjs`, `stable.cjs`, `empty-editor.cjs`, `modal-verify.cjs`, `geometry.cjs`, `parity.cjs`, `verify.cjs`: 再現用スクリプト。Playwrightのrequireパスはこの端末のバンドル環境

## 再現コマンド

```sh
cp performance/before.html /private/tmp/peta-board-performance.html
TARGET_URL=file:///private/tmp/peta-board-performance.html node performance/measure.cjs before.html before-file.json
cp peta-board.html /private/tmp/peta-board-performance.html
TARGET_URL=file:///private/tmp/peta-board-performance.html node performance/measure.cjs peta-board.html after-file.json
```

ダイアログだけを補足計測する場合は `MODALS_ONLY=1` と出力ファイル名を指定する。localhostでの検証には `python3 -m http.server 8765 --bind 127.0.0.1` を起動する。全計測を順に実行する。テスト用ブラウザーには利用者の通常のChromeプロファイルを指定しない。
