同じMac、Chrome 154.0.8037.99、Playwright headless、人工的なCPU・通信制限なし。375pxは画面幅の模擬で実スマートフォンではない。データは前回と同じfixtureで、0／50件は4列、500件は12列・各41〜42件。500件は本文2,400〜2,800文字、タグ2件、期限、チェック項目30件を持ち、保存JSONは約3.5MB。量と条件を揃えた合成データで、実ユーザーのデータ分布ではない。実ユーザーのブラウザープロファイルと保存データは使わない。

## ④ 変更内容と残る課題

既存の高密度判定 `count×84 > window.innerHeight` とフッターありの条件で、元から本文の表示高さが0pxになる要素にだけ `white-space:pre` を追加した。全文と改行・空白を保持し、見えない行の折り返し計算を省く。少件数・フッターなし・本文の表示領域がある条件は従来のpre-wrap。件数の変化とリサイズで既存のクラス更新が適用を切り替える。検索本文に一致する場合は従来どおり検索抜粋を表示する。検索・保存・データ検証・更新反映・権限や保存キーは変更しない。変更後の待ち時間をスクロール後へ移していない。

| 候補 | 効果・影響 | 判断 |
| --- | --- | --- |
| size containmentとcontent-visibility:autoの併用 | 初期表示の大幅な短縮見込み | リサイズ後の閲覧位置とAXのStaticTextが変わり不採用 |
| autoにoverflow-anchor／intrinsic-size指定を追加 | 閲覧位置の差を抑える見込み | 閲覧位置とAXの差が解消せず不採用 |
| 高密度本文のdisplay:block | レイアウト負担の削減 | 単発比較の候補。preのみより効果が小さく追加変更を採用しない |
| 高密度本文のcontain:strict | レイアウト／描画負担の削減 | 表示は合うがpre単独より効果が小さく追加変更を採用しない |
| 表示高さ0px本文のwhite-space:pre | 本文の折り返し計算を減らす。初期表示・題名検索・解除・復元・同期に影響 | 90表示条件と最終機能試験を通り採用 |
| 高密度カードだけのFlex配置 | 残る配置計算を減らす見込み | 単発188.2→187.2msと差が小さく、スクロール寸法4px差が出て不採用 |

候補の単発時間は選定用で、最終短縮率には使わない。profile.jsonの計装実験では500件起動のLayoutDurationが309.8→99.4ms、renderBoardが328.8→118.0msで、正規化は3.0→2.9ms、renderNoteの500回合計は5.2→5.4ms。検索照合は両版500回で、今回の効果は主に本文のレイアウト計算を減らしたことに対応する。計装の単発値と、反復した画面別の短縮率は区別する。
