# PetaBoard

個人の仕事・タスクを付箋で整理する、ローカルHTMLのボードです。タイトル・本文・タグ・期限・チェックリストを使い、列ごとに作業をまとめられます。アカウント登録は不要です。

## 使い方

1. `peta-board.html` をブラウザーで開き、各列の「付箋を追加」から書き始めます。何も書かずに編集画面を閉じた付箋は残りません。
2. 列名はクリック、ボード名は設定から変更できます。付箋はドラッグか編集画面の「列」で移動します。タッチでは右上のハンドルを使い、カード上のスワイプで一覧をスクロールできます。列内の順番は編集画面の「上へ」「下へ」、または付箋にフォーカスして `Alt` + `↑` / `↓` で変更できます。
3. 検索はタイトル・本文・タグ・チェック項目・列名が対象です。スペース区切りで絞り込み、結果件数を確認できます。検索中は一致した本文・チェック項目・省略されたタグを抜粋表示します。検索中に付箋を追加すると、作った付箋を見失わないよう検索を解除します。編集後に検索条件から外れた付箋には案内を表示し、「検索を解除して表示」で再表示できます。ボード上の `/` で検索へ移動、`Esc` で検索解除や編集画面を閉じられます。
4. 列・付箋・チェック項目を削除しても、30秒以内なら「元に戻す」で復元できます。連続した削除も猶予内なら順に戻せます。復元の猶予はこの画面を開いている間に限り、ボードの読み込み・初期化・別タブの更新反映時には終了します。`Tab` で付箋を選び、`Enter` で編集できます。列の並べ替えには左右の矢印も使えます。

列はすべて削除できます。0列の状態も保存され、「列を追加」から再開できます。

タイトル・本文・ボード名の文字数はラベル横に表示します。入力中、上限の80%以上、または入力エラー時に表示されます。上限を超える貼り付けは切り捨てずに拒否し、入力済みの文章を保持します。タグは「,」「、」「，」で区切れます。チェック項目で `Enter` を押すと、その直後に次の項目を追加できます。期限はカレンダー内で `YYYY-MM-DD` または8桁の `YYYYMMDD` を直接入力して設定できます。不正な日付は反映しません。

画面上の「使い方」は、基本操作・保存・バックアップ・ショートカットの説明だけを独立して表示します。ボード名、テーマ、初期色、バックアップの復元、初期化は「設定」にまとめています。キーボード操作と補足はヘルプ内で展開できます。表示は常にコンパクトです。

## 保存とバックアップ

変更はこの端末の、このブラウザー内へ自動保存します。画面上部と付箋編集画面に「保存中…」「自動保存済み」、保存の停止や復旧の状態を表示します。編集は「完了」または閉じるボタンで終了できます。HTMLファイル自体への書き込みやクラウド同期はありません。

「バックアップ」でボード全体をJSONとして書き出せます。復元は設定の「バックアップを復元」から行い、確認後に現在のボードを置き換えます。閲覧データの削除、端末・ブラウザーの変更、HTMLの移動・名前変更前に書き出してください。プライベートブラウズ終了時などに保存データが失われる場合もあります。

自動保存にはWeb Locksを利用できる環境が必要です。ローカルHTML、HTTPS、開発用のlocalhostで開いてください。保存失敗や複数タブの編集競合時は上書きを停止し、現在の内容の書き出し・再試行・保存済み内容の再読み込みを案内します。異常な保存データは既存の退避を保護し、次の保存が成功するまで元の原文も保持します。

JSON読み込みは32MiBまで、列12件・付箋500件までです。内容の切り捨てが必要なJSONは読み込みを拒否します。ブラウザーの保存容量は別の制限となり、容量不足時は画面に通知します。

## 開発・検証

HTML・CSS・JavaScriptは `peta-board.html` にまとめ、ビルド不要で直接開ける構成です。CSSはレイアウト・操作状態、業務UIの共通部品、アプリ固有の調整の順に定義しています。関連する子要素・状態・部品ごとの画面幅の調整は、ブラウザー標準のCSSネスト構文でまとめています。複数の部品に共通する画面幅の調整は各スタイルシートの末尾に置き、ボタン・入力欄の基本スタイルは共通UIに集約しています。利用にはCSSネスト構文に対応した現行ブラウザーが必要です。

ダイアログの背景・パネル・開閉状態は共通CSSにまとめ、サイズと重なり順は各画面で指定しています。付箋のクリック・キー・ポインター操作と列のドラッグ開始は常設のボード要素で受け取り、カレンダーの日付選択・フォーカス操作も常設のグリッドで受け取ります。SVGアイコンは種類ごとに解析結果を再利用し、変更のないアイコンは作り直しません。再描画・別タブ同期時のスクロール復元と、読み込み・同期時のデータ検証はそれぞれ共通の関数を通します。

操作アイコン全16種類とタブ用の付箋マークは、Google公式の[Material Symbols Outlined](https://github.com/google/material-design-icons)（24px、FILL 0）をSVGとして埋め込んでいます。月・太陽は `dark_mode` / `light_mode`、タブ用マークは `sticky_note_2` です。各定義のコメントに公式のシンボル名を記録し、公式SVGのパスを変更せず使用しています。フォントの外部読み込みは不要です。Apache 2.0ライセンス全文はHTML内に保持しています。

配布HTMLはビルド・npm・外部通信を必要としません。開発用の検査と回帰試験にはNode.js 24 LTS（24.21.0以上）、Python 3.15.0、npmを使います。Python 3.14.8との互換確認もローカルで行えます。Ruff 0.16.10のPython 3.15専用規則は開発中のため、静的検査は安定したpy314基準を維持し、Python 3.15で構文・実行結果を検証します。Pythonは仮想環境に `python -m pip install -r requirements-dev.txt` で検査用依存を導入してください。Python実行ファイルは `PYTHON` でも指定できます。`npm ci` と `npx playwright install chromium firefox webkit` の後、`npm run ci` で全JavaScriptの静的解析、HTML/CSS検証、検証スクリプトの整形、PythonのRuff検査・整形確認・過去6ランナーの出力比較、操作の回帰試験を実行できます。GitHub Actionsは削除・無効化しています。`npm run ci` はローカル検査をまとめて実行するコマンドとして維持しています。通常の検査結果は `performance/verification/` に保存し、過去の比較記録を上書きしません。3エンジンで試験する場合は `BROWSERS=chromium,firefox,webkit npm test` とします。既存Chromeを使う場合は `CHROME_PATH` で実行ファイルを指定できます。旧性能記録のHTMLと計測結果は比較資料として変更しません。HTMLをブラウザーで開いて動作を確認することもできます。検証用のブラウザー保存領域を分ける場合は、次のローカルサーバーを使えます。

```sh
python3 -m http.server 8765 --bind 127.0.0.1
```

`http://127.0.0.1:8765/peta-board.html` で開きます。ローカルHTMLの保存領域とは別になるため、実際のボードを移す場合はJSONバックアップを使用してください。

### ローカルHTML配布の追加検証

本番はローカルHTMLの配布です。検索中の列名編集で検索結果が変わらない場合、既存カードを保持します。500件・1440pxの前後各5試行では、同期入力処理221.3→5.6ms、結果と2フレーム待ちの代理指標260.4→33.0msでした。配布ファイルを直接開いた検証は比較環境の値と分け、[追加実装・配布版の検証記録](performance/followup/REPORT.md)に保存しています。

開発では `var`、`substr`、`hasOwnProperty` の直接呼び出し、`document.write`、`FileReader`、`onkeypress` を追加しません。標準DOM、`Object.hasOwn`、`Blob.text`、`const`/`let`を使います。付箋の変更は変更の有無を返す `withActiveNote` を通し、検索キャッシュを無効化します。Promiseのexecutorから値を返さず、例外・解放・キャンセルを明示します。検証データは共通fixtureを使い、依存・一時ファイル・ブラウザーのパスを端末に固定しません。配布物は引き続き単一HTMLです。

### 追加検証：検索の包含条件とリサイズ（2026-10-10）

配布HTMLは検証済みのSHA-256 `30143609a812f288974b3a84a93d1a07b544af5990c9f9fb3ca8696bee330bd2`を維持。列のCSS高さ上限を使う2案を実装したが、高さ変更後にリストのスクロール位置が20pxから0pxへ変わるため不採用。通常検索の短縮値とFirefoxの悪化を、本番の改善として扱わない。[追加報告](performance/round8/REPORT.md)に結果・生データ・不一致・5試行の同一版対照を保存した。

`scripts/search-render.mjs`は通常検索の寸法・状態比較を3エンジンで実行でき、`PRODUCTION_ONLY=1`では実際の配布HTMLを隔離コンテキストで計測する。比較用クラスの正規化は明示した検証候補だけに限定し、寸法・フォーカス・スクロール等は完全一致を要求する。起動失敗やassert失敗でも、ブラウザーと一時ディレクトリーの解放を`finally`で保証する。実行ソースを凍結し、ハッシュが計測時に変わった系列を最終値に使わない。配布版の変更がない場合、前回の検証を同一ハッシュの範囲で引用し、新しく実行した件数と混ぜない。
